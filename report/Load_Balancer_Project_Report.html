2. Performance-Based Dynamic Load Balancing

Instead of fixed round-robin, the Load Balancer evaluates real-time performance telemetry collected from all backends every 2.5 seconds. The load score is computed continuously as:

Load Score = (ActiveConnections × 0.40) + (CPULoad% × 0.40) + (AvgResponseTime / 20 × 0.20) Routing Rule: If CurrentBackend.Score > 65 (Threshold), switch to min(HealthyBackends.Score)

Dynamic Switching: The current backend remains active while its score is below the threshold (65). When load rises above 65, new requests switch immediately to the least-loaded healthy backend.

Health Monitoring: Any backend failing 3 consecutive health probes is evicted from the active pool and traffic fails over automatically. Recovered backends rejoin the pool with zero downtime.

3. Shared Database & Duplicate Prevention

  • Shared Persistence: Backends share /home/student/shared_db/chat_database.json.
  • Idempotency & No Duplicates: Every message has a unique message ID (client UUID or deterministic ID). An in-memory Set index detects duplicates in O(1) time. Redundant submissions are ignored and return status: "duplicate" without double insertion.
  • Atomic File Writes: State is saved via .tmp.[timestamp] atomic rename, preventing file corruption under concurrent writes.
